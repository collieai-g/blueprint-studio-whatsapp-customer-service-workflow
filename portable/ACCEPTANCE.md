# V2.0 驗收

在當次使用者授權的帳戶和範圍驗收。以下案例的結果各自記錄，包含實際時間、可見狀態及待補項目。

| 案例 | 實際驗收條件 |
| --- | --- |
| 從連結匯入 | 只交 GitHub Release 連結，核對 AI 能取得正確 ZIP、讀取 `START_HERE.md` 並解析預設設定。主機也可讀取直接上傳的同一 ZIP。 |
| 重新使用既有設定 | 匯入 V1 的 `timing` 及既有公司政策，核對巡查及停留值等值轉換，舊帳戶、基準和待辦只沿用已核實的私人狀態。 |
| 自動巡查 | 使用者授權後核對唯一排程的識別、工作聊天、有效頻率及啟用狀態。再次啟動或修改時間時核對同一排程及讀回結果，再確認一次實際定時觸發。 |
| 營業時段 | 用營業開始、結束、跨午夜及主機時區不同的例子核對當地時間。關門前已發出的回覆照常核實，未發出的內容留待下輪。 |
| 回覆限制 | 用一個連續來訊的對話及其他待答對話驗證每對話和全輪上限。到上限後保留餘下待辦。核對每則文字長度和補問數。 |
| 觀察窗口 | 首輪及無待答時按設定觀察。有成功發送時重新開始觀察期限。只有在線或輸入提示時等到當次期限。 |
| 中斷與恢復 | 以授權測試對話模擬發送後狀態未寫完的情況，恢復時先查證畫面再接續，確認同一訊息沒有重發。 |
| 停止與轉交 | 核對使用者停止後原排程已停用，以及客戶停止聯繫及需人工接手的事項保存在私人狀態。 |

可見的排程配置及發送狀態按實際觀察填寫。使用者自行回報的成功案例可記作回報測試。新主機、真實定時觸發及發送未觀察時列為待驗收。
